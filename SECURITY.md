# Security policy

## Report a vulnerability

Report vulnerabilities privately through [GitHub Security Advisories](https://github.com/pipelab-org/agent-evidence-levels/security/advisories/new). Don't open a public issue for an undisclosed vulnerability.

Include the affected commit or release, the impact, and enough detail to reproduce the problem without relying on private infrastructure. Please keep the report and any exploit details private until a fix or disclosure plan is agreed.

## Scope

Security reports may cover:

- normative specification language that could make an AEL result or trust boundary unsound;
- the `aelcheck`, `aelgen`, and `aelpackage` toolchain;
- package, artifact, status, and record schemas;
- conformance fixtures or release automation when they could produce or publish misleading evidence.

Questions about whether a product deserves a grade, proposed changes to the standard, and general support requests belong in the normal issue tracker unless they disclose a vulnerability.

## Support boundary

This project has no response-time or remediation SLA. Reports will be reviewed as maintainer availability allows. Acknowledging a report doesn't promise a particular fix, release date, or support period.
